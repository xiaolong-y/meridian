Quantinuum Details Nexus Hybrid Workflow Runtime Integration with Slurm and OpenQSE at SC26

Quantum Computing Report Mohamed Abdel-Kareem 13h quantum 309 words 2 min read

At the SC26 supercomputing conference in Chicago, Quantinuum outlined how its Nexus developer platform and asynchronous Hybrid Workflow Runtime (Tierkreis) connect quantum programming with supercomputing workload managers. Designed to coordinate multi-stage scientific pipelines without idling classical nodes while remote quantum jobs wait in queues, the runtime links Quantinuum’s Guppy programming language with existing high-performance computing (HPC) schedulers including Slurm, PBS, and PJSub.
Within the Open Quantum-HPC Software Ecosystem (OpenQSE) reference architecture led by Oak Ridge National Laboratory, Nexus’ Hybrid Workflow Runtime operates at the application workflow layer above cluster scheduling and resource-access interfaces such as the Quantum Resource Management Interface (QRMI) and Quantum Device Management Interface (QDMI). In Quantinuum’s SC26 demonstration, the runtime coordinates task dependencies and dispatches classical chemistry steps to a shared Slurm executor alongside NVIDIA’s Slurm 26.11 quantum resource extensions while routing quantum execution targets through QFw.
Quantinuum also highlighted a joint electronic-structure workflow with RIKEN implementing RIKEN’s quantum residual exploration method. Using Guppy to define quantum circuits and Tierkreis to manage classical-quantum handoffs, the team evaluated a stretched 12-atom hydrogen chain and showed that quantum-sampled electronic configuration proposals achieved lower calculated ground-state energies than classical-only selection using an identical number of final configurations.
