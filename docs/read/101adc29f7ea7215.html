qBraid Unveils qBraid OS and Launches Hosted GH200 GPU Simulators at NVIDIA GTC Berlin

Quantum Computing Report Mohamed Abdel-Kareem 4h quantum 554 words 3 min read

Quantum cloud orchestration platform qBraid has introduced qBraid OS, an agentic operating system designed for quantum hardware manufacturers and supercomputing centers to manage, schedule, and operate quantum processing units (QPUs). Unveiled at NVIDIA GTC Berlin, the software bridges physical quantum processors with CPU and GPU supercomputing clusters using the NVIDIA CUDA-Q platform and low-latency NVIDIA NVQLink interconnects.
In tandem, qBraid launched two hosted GPU-accelerated quantum simulators running on NVIDIA GH200 Grace Hopper Superchips in its Leo cluster: an exact state-vector simulator (`gpu-sv`) supporting up to 35 qubits and a tensor-network simulator (`gpu-tn`) supporting weakly entangled circuits up to 500 qubits.

qBraid OS Platform Infrastructure and GPU Simulation Benchmarks
Developed to replace fragmented, custom-built quantum control stacks, qBraid OS provides an integrated operational framework spanning account management, job queue scheduling, usage metering, and control-electronics interfaces. By integrating NVIDIA CUDA-Q and NVQLink, qBraid OS enables classical GPU nodes to perform real-time quantum error-correction (QEC) decoding and classical co-processing during active QPU execution cycles. Operational workflows and system setup can be automated via AI coding agents within operator-defined permission boundaries.
Complementing the operating system release, qBraid’s hosted GPU simulators deliver significant performance gains over classical CPU execution. On a 32-qubit random circuit (20 layers deep), the `gpu-sv` state-vector simulator executed in 2.7 seconds on a GH200 node compared to 2 minutes 43 seconds across 32 CPU server cores. To extend state-vector simulation beyond the GPU’s 96 GB HBM3 memory limit (which caps out at 33 qubits in single precision), `gpu-sv` leverages the GH200 superchip’s high-speed CPU-to-GPU coherent interconnect to store remaining amplitudes directly in the 72-core Grace CPU’s RAM, reaching 35 qubits without manual configuration.
For circuits exceeding 35 qubits, `gpu-tn` uses matrix product state (MPS) representations to scale up to 500 qubits, dropping low-weight entanglement contributions when bond dimensions exceed configurable thresholds (`maxBondDim`). Developers can access both simulators using OpenQASM 2, OpenQASM 3, or native Qiskit circuits via the standard `QbraidProvider` SDK.
