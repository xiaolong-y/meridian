IBM Releases Qiskit SDK v2.6 with C API Pass-Manager Framework, Native QPY Serialization, and Custom Operations

Quantum Computing Report Mohamed Abdel-Kareem 8h quantum 578 words 3 min read

Quantum software developer IBM Quantum (NYSE: IBM) has released Qiskit SDK v2.6, a major infrastructure update in its v2.x open-source compilation series. The release focuses on expanding Qiskit’s high-performance C API layer, bringing essential compilation capabilities to native C, C++, and Julia environments without requiring a Python runtime.
Qiskit v2.6 introduces a generic C API pass-manager framework (QkPassManager) that allows developers to write custom compiler passes and lower circuits through multiple type-checked intermediate representations (IRs). The update also exposes native binary QPY serialization directly to C and allows users to define custom, hardware-native quantum operations via a C vtable interface. These enhancements advance Qiskit’s roadmap toward Python-optional execution within tightly coupled High-Performance Computing (HPC) and Quantum-Centric Supercomputing (QCSC) architectures.

C API Pass Management and QPY Format v18 Upgrade
The new pass-manager framework extends Qiskit’s multi-representation compiler model introduced in v2.5. By utilizing QkIrHandle descriptors, passes explicitly declare their input and output representations (such as built-in QkCircuit or QkDag instances, as well as dynamically defined user IRs). The QkPassManager validates the full pipeline before execution, enabling structured, multi-stage compiler lowering for C, C++, Julia, and Fortran applications.
The update also makes QPY format v18 the default serialization standard across Qiskit. Format v18 provides a more compact on-disk encoding for quantum and classical registers, reducing file sizes for large-scale circuits. Circuits serialized from the C API remain fully compatible with Python’s qiskit.qpy module. Build requirements for compiling Qiskit from source have been updated to Rust 1.89 (MSRV), while the minimum supported runtime remains Python 3.10 (noting that Python 3.11+ will be required starting in Qiskit v2.7).
Qiskit GitHub Roadmap: Transitioning to Rust-Native Core and Fault Tolerance
Alongside the v2.6 release, IBM Quantum updated the official Qiskit GitHub Roadmap, detailing a multi-release progression through upcoming minor versions (v2.7 and v2.8) toward complete C ABI/API stability and fault-tolerant compilation pipelines:
- Qiskit 2.6 (Current): Delivers the C API pass manager, dynamic range support for control flow, native QPY v18 serialization, and initial removal of the Python linker dependency (libpython) from the core libqiskit library.
- Qiskit 2.7 (In Development): Will formally declare ABI and API stability guarantees for the C interface, while introducing a Medium Intermediate Representation (MIR) to support compilation to fault-tolerant instruction sets.
- Qiskit 2.8 (Planned): Focuses on deploying BackendV3—a Rust-native execution interface exposed to both Python and C/C++—and integrating the Samplomatic library into Qiskit’s quantum program datamodel.
