Pasqal Demonstrates Hybrid GPU-to-QPU Workflows Using Slurm 26.11 Hierarchical Resources, QRMI, and CUDA-Q

Quantum Computing Report Mohamed Abdel-Kareem 20h quantum 356 words 2 min read

Pasqal has detailed an end-to-end quantum-HPC scheduling integration combining NVIDIA’s Slurm 26.11’s Hierarchical Resources (HRES) framework with the open-source Quantum Resource Management Interface (QRMI) to manage neutral-atom quantum processing units alongside classical GPUs. Co-developed with IBM and demonstrated at SC26, the Lua-based qrmi_hres.lua plugin replaces legacy license-tracking and SPANK workarounds by allowing Slurm to monitor device availability, open authenticated sessions via Pasqal’s open-source Warden middleware, and schedule jobs across both cloud and on-premises QPUs.
Building on production deployments such as the Sol neutral-atom processor at Italy’s CINECA supercomputing center, the integration lets administrators define QPU concurrency limits and maintenance polling intervals directly inside Slurm’s resources.yaml configuration file. For on-premises systems protected by Warden, the Slurm controller acquires and revokes user-scoped session tokens automatically via MUNGE authentication, ensuring jobs wait in queue during hardware calibration and release access cleanly upon completion or cancellation.
To connect cluster scheduling with application development, Pasqal demonstrated multi-stage batch pipelines pairing Pulser and NVIDIA CUDA-Q 0.17 across classical GPUs and physical neutral-atom hardware. Using CUDA-Q’s GPU emulation target (emulate=True), a dependent Slurm workflow can first validate a Rydberg-blockade parameter sweep on a GPU node and automatically trigger execution on a physical processor such as Pasqal’s FRESNEL_CAN1 system only if the classical simulation succeeds.
