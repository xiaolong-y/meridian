Quantum Machines Demonstrates Sub-Microsecond Surface-Code Decoding on OPX1000 Using NVIDIA CUDA-Q QEC and NVQLink

Quantum Computing Report Mohamed Abdel-Kareem 19h quantum 387 words 2 min read

Quantum Machines (QM) has demonstrated mid-circuit quantum error-correction (QEC) decoding on its OPX1000 quantum control platform by integrating the NVIDIA CUDA-Q Realtime API and transport-agnostic CUDA-Q QEC decoding server over NVIDIA NVQLink. Executed on an NVIDIA GH200 Grace Hopper server using pre-sampled surface-code memory syndromes at a 0.1% physical error rate, the bridge maintained a 2.4 μs round-trip controller-to-decoder communication latency while achieving sub-microsecond per-round decoding for code distances 7 and 11.
0.19 to 0.22 μs per round (steady 2.4 μs round-trip link).
Distance 11
25, 50, and 75 QEC rounds
0.56 to 0.67 μs per round (below 1 μs cycle target).
Distance 15
25, 50, and 75 QEC rounds
1.20 to 1.50 μs per round (target for GPU dispatch optimization).
To execute real-time feedback within a single quantum program, QM implemented a CUDA-Q Realtime bridge that compiles CUDA-Q static memory circuits through Quake to QUA and streams syndrome measurements via enqueue_syndromes and get_corrections calls during circuit execution rather than in post-processing. Because the CUDA-Q QEC decoding server decouples decoder handlers from transport networking code, users can swap between algorithms such as PyMatching and NVIDIA’s fusion decoder via YAML configuration edits without modifying control firmware.
The initial release routes callbacks through host CPU dispatch threads on the GH200 accelerator server, with direct GPU dispatch planned for subsequent updates. Early access to the OPX1000 CUDA-Q QEC integration will open to customers in December 2026.
